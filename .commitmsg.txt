ci: 修复 release workflow 的版本同步、校验与发布幂等性

发布 v0.3.0 时暴露出的几个问题，以及对应修复：

- npm version 在目标版本与当前版本相同时会报 "Version not changed" 直接失败。
  仓库的 package.json 恒为 0.1.0（由 CI 同步），一旦 tag 版本与之相同，
  发布流程会在第一步就挂掉。改为直接改写 package.json，行为稳定可重复。
- tag 版本号没有校验，非法版本号会带进后续步骤产生难懂的报错。现在提前用
  semver 正则拦截，并拒绝 npm 不接受的前导零版本（01.2.3）。
- 同步 package-lock.json 里的版本号，避免 npm ci / npm publish 时版本不一致。
- 发布前没有跑测试。新增的 37 个单测此前完全没进 CI，等于没有作用。
  现在 Test 步骤在 Build 之前执行，测试不过就不会发布。
- npm publish 不幂等：发布失败后重跑整个 workflow 会卡在
  "cannot publish over the previously published version"。现在先检查版本是否
  已在 registry 上，已发布则跳过发布步骤，仅重建 GitHub Release。
- Verify package 之前只打印版本号不做校验，现在比对 package.json 与 tag
  是否一致，不一致直接失败。
- 增加 concurrency 组，避免 tag 密集推送时多个发布任务互相覆盖 npm dist-tag。
- Create GitHub Release 增加 fail_on_unmatched_files: false，避免因打包产物
  缺失导致整个发布任务失败。

同时补上 npm view 已发布版本时的幂等判断（版本不存在时 npm view 返回非零
退出码，已显式区分，不会误判）。
